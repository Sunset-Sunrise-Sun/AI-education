# Case A 人工验收清单

给**人工测试者**用。逐条勾选；每条都写明「怎么验」与「通过标准」。

前置：按 `docs/e2e/CASE_A_PLANNING_DEMO_RUNBOOK.md` 起好后端与前端。

> ⚠️ 本清单只覆盖**已实现**的行为。清单里出现的一切都不代表 AI 已自动决策：
> 编排是**固定工具**，规划是**确定性启发式**，换班必须**人工确认**。

---

## A. 输入与身份

- [ ] **A1 上传成绩单**
  验：选择一份中山大学成绩单 PDF 并上传。
  通过：摘要有课程条数与学期数；**没有**任何姓名 / 学号 / GPA 出现在页面或请求里。

- [ ] **A2 待核验课程号**
  验：看成绩单摘要与补修列表。
  通过：真实 PDF 没有官方课程号时，如实显示"待核验"；⛔ 系统**不**按课程名自动抵认。

- [ ] **A3 当前课表：搜索加入**
  验：搜索一门课（如 `CSE201`），点某个教学班的「加入当前课表」。
  通过：搜索结果**不超过 20 条**；加入后当前课表出现该条，身份为
  `学期 + 课程号 + 教学班号`。

- [ ] **A4 当前课表：批量 / 手工录入**
  验：用批量输入或手工录入加入若干条。
  通过：条数与课程数一致；重复加入同一教学班不会产生重复项。

- [ ] **A5 手工录入需要明确确认**
  验：手工录入若干条后，**不勾选**确认直接生成。
  通过：被拦下并提示需要本人确认；⛔ 不会带着未确认的手工数据继续。

- [ ] **A6 确认后又被改动会作废**
  验：确认手工录入 → 再改动课表。
  通过：出现"之前的确认已作废，请重新确认"的提示；⛔ 不会沿用旧确认。

- [ ] **A7 `meetings=[]` 的语义**
  验：找一条排课信息缺失的教学班。
  通过：显示「排课信息待核验」（或等价的中性表述）；
  ⛔ **不得**显示成"没有课""无需上课""无冲突"。

- [ ] **A8 教师缺失**
  验：看任一教学班的教师。
  通过：显示「任课教师：待核验」；⛔ 不出现编造的教师姓名。

## B. 偏好与生成

- [ ] **B1 意向课程（课程级去重）**
  验：把同一门课加入两次。
  通过：只保留一条（课程级）；写入的是课程号，不是教学班号。

- [ ] **B2 设置偏好**
  验：设置学分上限 / 跨校区 / 不方便时间。
  通过：界面使用学生化文案；⛔ 不出现 `max_credit` / `avoid_cross_campus` 这类技术字段名。

- [ ] **B3 生成方案**
  验：点「生成并优化我的转专业学业方案」。
  通过：出现补修缺口、本学期推荐课表、待确认调整、未来学期路径；
  ⛔ 失败时**不会**悄悄回退到 Mock。

## C. 本学期：建议 → 确认 → 生效

- [ ] **C1 生成建议不改课表**
  验：生成方案后，**不要**点任何按钮，对比当前课表。
  通过：当前课表与生成前**完全一致**；⛔ 系统不会自动替你做任何替换。

- [ ] **C2 建议只来自结构化候选**
  验：看「待你确认的调整」区块。
  通过：每条建议都给出**当前教学班 → 候选教学班**，以及候选的上课时间、校区/教室、原因。
  若当前输入下没有可确认无冲突的候选，则**不出现**「采用调整」按钮，
  只显示中性的"需要明确选择"说明。

- [ ] **C3 显式确认后才生效**
  验：点某条建议的「采用调整」。
  通过：该课程的当前教学班换成候选教学班；**其余课程不变**；
  页面显示"已按你的确认…"。

- [ ] **C4 周课表刷新**
  验：确认一条换班后看本学期周课表。
  通过：周课表反映新的教学班；⛔ 不是前端自己拼的，而是后端返回的课表。

- [ ] **C5 暂不调整不改状态**
  验：点某条建议的「暂不调整」。
  通过：该条在本页收起；课表**不变**；刷新页面后建议仍在（因为后端状态没变）。

- [ ] **C6 非法换班被拒**
  验：换一条**不属于同一课程**或**不属于同一学期**的候选（若界面无法构造，
  可由开发者用接口直接测）。
  通过：被拒绝且给出原因；课表**不变**；⛔ 不假装成功。

## D. 未来学期路线图

- [ ] **D1 真实学期与培养方案学期号**
  验：看未来学期区块的每个学期标题。
  通过：同时显示**学期标签**（如 `2026-2`）与**培养方案第 N 学期**；
  ⛔ N **不是**"列表第几项"。

- [ ] **D2 只有课程级信息**
  验：逐条看未来学期的课程。
  通过：只有课程名、课程号、学分、必修/选修、安排原因；
  ⛔ **不出现**教学班号、教师、星期、节次、教室、校区、容量。

- [ ] **D3 分类正确**
  验：看课程上的分类标签。
  通过：必修 / 选修 与培养方案一致；
  ⛔ **不**把整个选修池都标成必修。

- [ ] **D4 选修学分进度**
  验：看「选修学分进度」区块。
  通过：显示最低学分要求、已确认完成、本学期已选、规划前缺口、本次规划、规划后仍缺；
  且满足 **最低要求 − 已确认完成 − 本学期已选 = 本次规划 + 规划后仍缺**。

- [ ] **D5 证据不足不猜**
  验：当本学期已选课程无法确认归属选修组时看进度。
  通过：该项计 0 并显示为「—」或明确提示证据不足；
  ⛔ 不编造一个数字。

- [ ] **D6 unresolved / warnings 可见**
  验：看路线图底部的说明区块。
  通过：需要人工确认的事项与规划说明**如实展示**；⛔ 不被隐藏、不被改写成结论。

## E. 安全与数据

- [ ] **E1 页面与请求里没有隐私数据**
  验：看页面文本与浏览器网络请求。
  通过：没有姓名、学号、GPA、Cookie、Token。

- [ ] **E2 数据范围标注正确**
  验：看「本次规划数据」区块。
  通过：数据范围标注为**南校园 + 深圳校区**；「全校完整学期数据」为**否**。

- [ ] **E3 不联网抓数据**
  验：整个流程中观察后端日志。
  通过：⛔ 没有任何对学校教务系统的请求；全部数据来自本地已验收 artifact。
