# 开发细则

## 1. MVP 原则
优先保证：正确、可测试、可运行、可交接。避免无必要的复杂架构。

## 2. 模块内部
- 优先复用现有实现；
- 核心函数职责清晰；
- 对外输入必须校验；
- 错误要明确，不静默吞异常；
- 核心逻辑必须有测试。

## 3. 数据
跨模块只使用公共 Schema。模块内部可使用私有结构，但进出模块边界必须转换成公共格式。

## 4. 第三方依赖
新增前检查项目是否已有同类能力、是否必要、维护状态和部署成本。重要依赖需人工确认。

## 5. 测试
至少覆盖：正常、空输入、非法输入、边界情况和一个主要失败场景。

## 6. 错误信息
错误必须让非专业开发成员能理解，例如：
```text
课程 weekday=9 非法，weekday 应为 1~7。
```
而不是只返回 `ValueError`。

## 7. 文档同步
功能状态变化后更新 STATUS；阶段性工作追加 WORKLOG；公共接口变化必须先获批准再更新接口文档。
