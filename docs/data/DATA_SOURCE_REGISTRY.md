# 数据源登记表（Data Source Registry）

> **状态：登记模板（空表）。** 目前**没有任何已确认的数据源**，因此所有行的来源信息均为「待填写」。
>
> **硬性规则：本表不得填写未经人工确认的链接或机构信息。** 宁可为空，也不允许写入推测出来的 URL。
>
> 本表是 `DATA_ACQUISITION_PLAN.md` 第 3 节"预计来源"的落地登记处。
> 规划说"预计从哪来"，本表记录"**实际确认过**的来源是什么"。

---

## 1. 用途

1. 让每一个真实数据都有**可追溯的出处**（`/AGENTS.md` 第 18 节：Real 数据必须能说明来源，不得凭空补齐）；
2. 记录每个来源的**授权与合规属性**（是否官方、是否公开、是否需要登录、可否入库）；
3. 区分 **Raw / Sanitized / Mock**，避免三者混淆；
4. 让负责人能在不读代码的情况下，一眼看清"我们到底拿了哪些真实数据"。

---

## 2. 字段定义

| 字段 | 含义 | 填写要求 |
|---|---|---|
| `source_id` | 数据源唯一编号 | 见第 3 节命名约定；**一经分配不得复用** |
| 数据类别 | 对应 D1–D5 中的哪一类 | 必须与 `DATA_ACQUISITION_PLAN.md` 编号一致 |
| 来源机构 | 发布该数据的机构（学校 / 教务处 / 学院 / 教务系统等） | 必须为**实际确认过**的机构名，不得推测 |
| 来源标题 | 文件或页面的正式标题 | 照抄原标题，不要改写 |
| 来源 URL / 文件位置 | 链接或本地文件位置 | **未确认时一律填「待填写」**；禁止写入推测链接 |
| 是否官方 | 是否为学校官方发布 | `是 / 否 / 待确认`；非官方来源必须注明性质 |
| 是否公开 | 无需登录即可访问 | `是 / 否 / 待确认` |
| 是否需要登录 | 获取是否需要本人账号 | `是 / 否 / 待确认`；为"是"时必须注明"仅限本人权限内" |
| 发布时间 / 适用学年 | 文件的发布日与适用学年 | 只写文件上确实标注的信息，不推测 |
| 适用专业 / 对象 | 该来源适用于哪些专业或对象 | 用于判断能否用于当前 Demo 案例 |
| 获取日期 | 实际取得数据的日期 | `YYYY-MM-DD`；未获取则填「未获取」 |
| Raw / Sanitized / Mock | 该来源产出的数据层级 | 三选一，见 `DATA_ACQUISITION_PLAN.md` 第 5.1 节 |
| 备注 | 授权限制、脱敏说明、使用条件等 | 必须写清"限制"而不是只写"允许" |

## 3. `source_id` 命名约定

```text
POLICY-###        政策类（D1）
CURR-OLD-###      原专业培养方案（D2）
CURR-NEW-###      新专业培养方案（D3）
TRANSCRIPT-###    已修课程记录（D4）
OFFERING-###      课程开设 / 教学班数据（D5）
```

规则：

- `###` 为三位序号，从 `001` 开始；
- **编号一旦分配，即使该来源后来作废也不得复用**（在备注里写"已作废"）；
- 同一份文件的不同获取批次，沿用同一 `source_id`，在备注里记录批次与日期；
- 同一文件的 Raw 与 Sanitized 版本**使用同一个 `source_id`**，靠"Raw / Sanitized / Mock"列区分。

## 5. 填写规则

1. **先确认，后填写**：任何字段在人工核实前只能写「待确认 / 待填写」，不得凭印象补全。
2. **不写推测链接**：不确定的 URL 一律留空；宁可让负责人去确认，也不要写一个"看起来对"的地址。
3. **官方与非官方必须区分**：来自论坛、学长经验帖、第三方整理的内容可以登记，但"是否官方"必须写"否"，且不得作为判定依据。
4. **登录类来源必须写明边界**：在备注里写明"仅限本人正常登录后已有权限查看的范围"。
5. **Raw 一律登记为不可入库**：备注必须显式写出限制，而不是只写"注意脱敏"。
6. **作废来源不删除**：改为在备注写"已作废（原因 + 日期）"，保留追溯链。
7. **登记不等于获得授权**：登记只表示"我们知道有这么个来源"，实际取用仍需负责人批准。
