## 4. 字段覆盖统计（唯一允许的统计口径）

**样本总记录数 = 24 条**（已修课程记录）。

### 4.1 字段完整性

| 字段 | 有值记录数 | 覆盖率 |
|---|---|---|
| `course_id` | 24 / 24 | **100%** |
| `course_name` | 24 / 24 | **100%** |
| `credit` | 24 / 24 | **100%** |
| `semester` | 24 / 24 | **100%** |
| `passed` | 24 / 24 | **100%** |
| `course_type` | 24 / 24 | **100%** |
| `offering_unit` | 24 / 24 | **100%** |
| `cultivation_type` | 24 / 24 | **100%** |

**全部 8 个字段均为 100% 覆盖**，无缺失值。

### 4.2 取值域观察（用于判断 Schema 能否承载）

> 本节只记录**数据结构形态**，用于回答"字段长什么样"，**不描述该学生的学业结果分布**。

| 字段 | 观察 |
|---|---|
| `course_id` | 均为唯一值（无重复课程行）；形态与培养方案中的课程号一致（字母前缀 + 数字） |
| `credit` | 数值型；范围 **1 – 5**，**无 0、无负值**（用于核对 Schema 的 `minimum: 0`） |
| `semester` | 类型为字符串；**覆盖两个学期**（形如 `2025-1` / `2025-2`），即记录天然**按学期分组** |
| `passed` | **覆盖率 24/24**；类型 / 语义 = **boolean**，表示"某学生一次修读**是否通过**"。<br>**本轮不公开该样本的实际通过 / 未通过分布** |
| `course_type` | 类型为字符串；样本中出现 **公必 / 专必 / 专选 / 公选** 四类取值。<br>**本轮不记录各类的数量分布** |
| `offering_unit` | 类型为字符串；观察到**多个不同开课单位** |
| `cultivation_type` | 类型为字符串；样本中为**单一取值**；**其完整取值域未知** |

> 说明：上表只给出**覆盖情况与取值域**，**不含任何逐行课程清单**，也不含具体成绩。

## 5. 能证明什么

1. 中山大学教务系统中**确实存在**该案例学生的已修课程记录，且可通过本人正常权限取得；
2. 这批记录**同时具备** `course_id` / `course_name` / `credit` / `semester` / `passed` /
   `course_type` / `offering_unit` / `cultivation_type` **八个字段**，覆盖率均为 100%；
3. **`course_id` 确实可得**（推翻此前"成绩单不提供课程号"的假设）；
4. 已修课程记录**天然按学期分组**（本样本为 2 个学期）；
5. 记录中出现的 `course_type` 取值（公必 / 专必 / 专选 / 公选）与培养方案中的**课程模块口径一致**；
6. 存在**两个真实附加字段** `offering_unit` 与 `cultivation_type`，当前公共 Schema 中没有对应表示。

---

## 6. 不能证明什么

- **不能**证明学生缺什么课（那需要 Curriculum Diff，本轮不做）；
- **不能**证明任何两门课等价、或某课可以抵认 / 转换（属 Curriculum + 正式人工规则）；
- **不能**证明具体成绩、GPA、排名（本轮不接触、不恢复、不推断）；
- **不能**证明 `cultivation_type` 的完整取值域（样本内**只有一个取值**，无法判断是否还有"辅修"等其他取值）；
- **不能**证明 `offering_unit` 与"开课院系"是否完全同义（本轮只记录该字段存在）；
- **不能**由外部访问者通过公开 URL 独立复核（来源需登录）。

## 7. 关于"申请成绩转换"页面右侧培养方案对照状态（汇总结论）

负责人在该页面右侧观察到"**培养方案内课程信息**"，页面说明中存在按颜色区分的状态
（红 = 应修但未修的必、专课程；白 = 与培养方案一致；灰 = 已申请转换；蓝 = 已修的非培养方案课程）。

**本条只记录一条汇总结论**：

> 教务系统内**存在官方的"成绩转换 / 培养方案对照"状态**。
> 该状态可作为**后续 Curriculum 模块结果的外部验收参考**。

⚠️ **本轮严格未做**：

- **未**把页面右侧"红色课程"当作本项目 Curriculum Diff 的输出；
- **未**把红色课程复制进 `mock_data`；
- **未**依据任何颜色状态进行课程等价判断或补修判定。

是否进行「`MakeupTask[]` vs 官方页面状态」的独立验证，**由 Reviewer 在 Curriculum 实现完成后决定**。
