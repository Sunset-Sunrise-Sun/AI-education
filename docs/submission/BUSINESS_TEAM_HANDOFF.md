> 这份是下午直接发给负责商业与竞赛包装的同学看的。

## 二、可以自由优化（放心改）

这些地方你随便发挥，改了不会出问题：

| 可以改 | 说明 |
|---|---|
| **标题表达** | 主标题、副标题、每页 PPT 的标题都能重写。建议保持"学航·转衔"不变，其余随你 |
| **PPT 视觉** | 配色、版式、图标、图示风格、动画节奏，全部由你定 |
| **故事节奏** | 哪一页先讲、哪里放一个转折、哪里留一个停顿，按你的判断来 |
| **商业价值描述** | 对学生、对学校、对项目的价值怎么讲，可以从你的角度重写。⛔ 只要不加没有出处的数字 |
| **场景化语言** | 把"学生面对的处境"写得更具体、更有画面感。比如把七个问题写成一个学生的内心独白 |
| **比喻和类比** | 用"拼图""接力棒""断掉的路"这类比喻都行，只要不改变事实边界 |
| **排版与字数** | 删句子、改语序、压缩段落都行。宣传页要求文案短，删得越多越好 |
| **演示脚本的语气** | 台词可以改得更口语、更有节奏。⛔ 但禁语清单和数字口径不能动 |

## 三、不允许改掉的事实

这一节是**硬线**。改掉任何一条，材料就会在评委面前站不住。

### 1. 真实数据范围

**必须写成：真实教学班数据，范围是南校园 + 深圳校区。**

- ⛔ 不能写成"全校课程数据"；
- ⛔ 不能写成"完整学期数据"；
- ⛔ 不能因为"听起来小"就省略这半句。**这半句是可信度，不是缺点。**

### 2. 当前学期与未来学期的边界

| | 当前学期 | 未来学期 |
|---|---|---|
| 粒度 | **教学班级**，精确到具体教学班 | **课程级**，只有课程名、课程号、学分、必修或选修 |
| 会不会出现教师 / 教室 / 时间 | 会，有真实数据才显示 | ⛔ **绝不出现** |

⛔ 不能说"未来学期也帮你排好了课表和老师"。

### 3. 那个数字：12 加 11

页面上会出现 **23**，写法只有一种：

> **23 项历史培养要求评估：12 项已确认满足，11 项待人工确认。**

⛔ **绝对不能写成"需要补修 23 门课"。**
⛔ 也不能把这 11 项说成"就是你要补的课"，它们还需要人工确认。

> 顺带提醒：目标专业的选修毕业要求也是 **23 学分**。这是另一个 23，跟上面的 23 项评估完全不是一回事，写材料时别混。

### 4. 不自动选课

系统只给建议方案。⛔ 不能写"自动选课""自动注册""帮你把课选好"。

### 5. 不自动认定等价

课程等不等价、学分怎么算，属于学校正式规则。系统只列依据，不下结论。
⛔ 不能写"系统自动认定这门课可以抵"。

### 6. 必须有人的确认

三处不能删：

- 换班建议**必须用户本人确认**才生效；
- 手工填的课表**必须本人勾选确认**才会被采用，之后改动课表确认会自动作废；
- 课程认定类结论**必须人工确认**。

### 7. 当前 AI 能力边界

必须保留的说法：

> 规则驱动 + 结构化数据 + 确定性规划；固定工具编排，AI 增强模块待进一步接入。

⛔ 不能说"AI 已经自动推理并规划"；
⛔ 不能说"已接入大模型 / 检索增强 / 知识图谱"；
⛔ 不能说"用了全局优化求解"；
⛔ 不能说"这是最优方案"。

### 8. 其他三条边界

- ⛔ 不能说"教师数据已完整覆盖"（缺失时显示待核验，系统不编造）；
- ⛔ 不能说"排课信息空的班就是没冲突"（那是未知，不等于没冲突）；
- ⛔ 不能写任何没有出处的数字：准确率、用户量、提升倍数、市场规模、访谈结论、往届反馈。

## 四、数字都从哪里来

材料里出现的每一个数字，都应该指回这里。指不回去的，删掉。

| 数字 | 含义 | 来源 |
|---|---|---|
| **23 项** | 历史培养要求评估条数 | `docs/status/curriculum.md` 中 Case A 实际投影结果 `makeup_task_count = 23` |
| **12 项** | 其中已确认满足 | 同上，`satisfied 12` |
| **11 项** | 其中待人工确认 | 同上，`manual_confirmation 11` |
| **23 学分** | 目标专业选修组最低毕业学分（**另一个 23**） | 同上，选修组 `minimum_credit = 23` |
| **南校园 + 深圳校区** | 教学班数据范围 | `docs/data/CASE_A_SCOPE_AND_CURRENT_SCHEDULE.md`，`is_full_semester: false`、`is_whole_school: false` |

> ⚠️ 上面这些是仓库里**记录在案的实测值**。
> 现场演示时如果页面显示的数字与此不同，**以现场页面为准**，⛔ 不要念材料里的旧数字。

另外提醒：不要写后端测试通过数量、代码覆盖率之类的数字来当效果证明。评委会问的是"解决了什么问题"，不是"跑了多少个测试"。

## 五、建议这样改故事和视觉

### 故事方面

1. **开场别讲技术。** 从"一个大二学生刚转完专业，手上有成绩单、培养方案、没排完的课表"开始，比任何架构图都有效。
2. **把七个问题讲成一句人话。** 比如："他不是不知道选什么课，他是不知道从哪里开始。"
3. **把"不确定"当成卖点讲。** 如果有一页专门讲"哪些结论系统不敢下"，评委会记住这个项目。诚实比完美更有说服力。
4. **结尾落在"人做决定"上。** 系统的位置是给依据，不是替人做决定。这句话很适合做最后一页。

### 视觉方面

1. **一张图只讲一件事。** 架构图不要和流程图画在一起。
2. **给"待确认"一个专用颜色。** 全套材料里，凡是待人工确认、待核验的地方都用同一个颜色，形成记忆点。
3. **范围标签要显眼。** "南校园 + 深圳校区"建议放在每张涉及教学班的页面角落，别做成小字脚注。
4. **未来学期那一页，把"不提供"画出来。** 在学期卡片旁边放一个灰色的"教师 / 时间 / 教室：不提供"，让评委一眼看到这是刻意的设计，而不是漏了。
5. **对比图胜过长图。** 换班确认前后做左右对比，比一张全屏课表截图有说服力。
6. **少用英文。** 能把"待人工确认"写成中文，就不要用 `manual_confirmation`。

## 七、下午建议的工作顺序

1. **先读** `OPC_NARRATIVE.md`（十分钟，建立整体感觉）；
2. **再读** `MATERIAL_FACT_CHECK.md` 的第四部分"最容易讲错的十条"（五分钟，这是防错清单）；
3. **然后**打开 `PITCH_DECK_OUTLINE.md`，直接开始做 PPT；
4. **做到哪一页有疑问**，就回 `OPC_NARRATIVE.md` 找对应的说法；
5. **全部做完后**，拿 `MATERIAL_FACT_CHECK.md` 全文检索这几个词检查一遍：`23`、`12`、`11`、`南校园`、`深圳`、`教学班`、`自动`、`最优`、`AI 已经`。

有任何一条拿不准能不能说，就查事实核对表；查不到就**不要写**，或者留一个 `[待确认]` 标记问回来。

## 八、三句话记住项目

### 第一句：它是什么

**学航·转衔：面向转专业学生的 AI 学业路径重构 Agent。**
把学生转专业之后散落一地的课程问题，重构成一条可执行、可解释、可确认的学业路径。

### 第二句：它不是什么

⛔ 不是普通选课助手。
⛔ 不是通用课程问答机器人。
⛔ 不是教务系统替代品。

### 第三句：它的底线

**只给能证明的结论。不确定就说不确定。建议由系统给，决定由人做。**

## 九、最后一句

这套材料的价值不在于写得多漂亮，而在于**每一句话都查得到出处**。

你在润色的时候，只要守住第三节那八条硬线，剩下的地方随便发挥，都可以做得比现在更好看。
