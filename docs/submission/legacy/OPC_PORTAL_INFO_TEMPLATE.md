# OPC 门户填报信息模板（逐字段）

> **用途**：把提交门户（报名平台）需要逐字段填写的文本集中到一处，填的时候直接复制，⛔ 不要临时改写口径。
>
> **本文件的性质**：
> - 每个字段三段式 —— `字段名` / `建议填写内容（可直接用）` / `状态`；凡是需要人工补充的字段，额外给「填写提示」。
> - **状态取值**：
>   - `已确定（仓库可核实）`：内容来自本仓库事实（README / 架构文档 / 代码契约），可直接使用；
>   - `[OWNER TO FILL]`：属于个人 / 团队 / 学校 / 联系方式 / 门户链接等**本项目无法自行核实**的信息，⛔ 不得由 Agent 编造；
>   - `待核实（依赖官方规则）`：内容本身已写好，但填报口径取决于官方赛规，须先核对 `OFFICIAL_RULE_CHECK.md`。
> - **定位口径（全文件唯一，⛔ 不得偏离）**：
>   **学航·转衔：面向转专业学生的学业路径重构原型（固定工具编排，AI 增强待接入）**
> - ⛔ 本文件不含任何团队成员、学校背书、用户数、准确率、部署与商业验证信息；这类内容一律 `[OWNER TO FILL]` 或如实写"无"。
> - 相关既有材料：`docs/submission/OPC_PITCH_PACK.md`（口径与红线）、`docs/submission/OPC_FINAL_SLIDES_CONTENT.md`（幻灯片内容稿）、`README.md`（项目事实源）、`docs/architecture/COMPETITION_ARCHITECTURE.md`（架构图与链路）。
>
> ⚠️ 本文件**不主张**任何官方资格结论，也**不主张**本项目已满足任何特定赛规；填报前请先看 `OFFICIAL_RULE_CHECK.md`。

## 12. 痛点

**建议填写内容（可直接用）**

```text
1. 培养方案差异难以自查：转入新专业后，原专业已修课程与新专业培养要求的对应关系分散在文档与条款里，学生很难自己判断哪些已满足、哪些还需要补。
2. 补修判定涉及正式规则：课程是否等价、能否替代属于学校正式规则与审批范围，学生自行推测容易出错。
3. 供给与课表约束叠加：即使确定了要补哪些课，还要在一个学期内同时满足时间、节次、周次与校区约束，需要人工反复试排。
4. 结论不易解释：即使排出一个方案，学生也往往说不清为什么这样排、哪里还有风险、哪些地方必须找老师确认。
```

**状态**：`已确定（仓库可核实）`

**填写提示**：与 `README.md` §2「痛点（不夸大）」四条一一对应；⛔ 不要添加未经调查的比例、人数或时间成本数字。

**建议填写内容（可直接用）**

```text
1. 培养方案解析与差异：解析原 / 新专业培养方案与已修课程记录，给出新旧方案差异与课程匹配建议。

5. 冲突识别与受限修复候选：已实现确定性时间检查、受限组合可行性检查与替代教学班候选评估；保留已有班，仅提出新增 / 候选建议，并把无法确定的事项保留到 unresolved / 人工确认。
6. 风险与未决事项呈现：页面展示 PlanResult 中的 risks[] / unresolved[]，由人做最终确认。
```
