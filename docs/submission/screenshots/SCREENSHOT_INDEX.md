## 逐张索引

### 01_成绩单上传.png
- **取景**：第一步「上传成绩单」区块
- **用途**：证明输入起点是学生本人成绩单
- **配文**：「学生从上传本人成绩单开始。系统只取课程名称、学分、成绩与学期；姓名、学号、绩点不读取、不展示。」
- **不能证明**：不证明成绩单内容已被学校核验

### 02_当前课表输入.png
- **取景**：「第二步：填写当前课表」搜索区 + 当前课表摘要
- **用途**：证明每条身份是「学期 + 课程号 + 教学班号」，且数据范围已标注
- **可见文字**：「已加载真实教学班数据 4069 条；数据范围为南校园 + 深圳校区」
- **不能证明**：不证明全校课程覆盖

### 03_学业方案总览.png
- **取景**：「我的转专业方案」总览条
- **用途**：一屏讲清方案给了什么，适合做 PPT 完成度页主图
- **画面数字**：本学期预计学分、补修课程（含待确认数）、专业选修学分、需要我确认项数、未来学期数
- **不能证明**：不证明这些建议一定可执行

### 04_成绩单参与判定说明.png
- **取景**：成绩单与已满足判定的说明条（在方案结果**之前**）
- **用途**：证明系统如实说明"上传的成绩单没有参与已修完 / 已满足的判定"
- **配文**：「已满足事实来自已确认的培养方案事实，不是靠成绩单自动抵认。」

### 05_本学期推荐课表.png
- **取景**：本学期周课表（按真实教学班绘制）
- **用途**：证明本学期规划精确到真实教学班
- **可见文字**：课程名、课程号、教学班号、时间、校区；教师位置显示「教师信息暂未同步」
- **不能证明**：不证明已完成选课或注册

### 06_本学期专业选修建议.png
- **取景**：「本学期专业选修建议」区块（含学分负荷提示）
- **用途**：证明选修学分缺口能落到本学期，且系统不替学生选课
- **可见文字**：候选课程名 / 课程号 / 学分 / 可用教学班数 / 冲突状态；「加入考虑」按钮
- **不能证明**：不证明这些课一定能选上

### 07_本学期学分负荷.png
- **取景**：学分负荷提示条
- **用途**：证明学分负荷受控
- **可见文字**：当前已选 / 建议新增补修 / 建议专业选修 / 预计合计

### 08_换班建议与需要你处理.png
- **取景**：换班建议区块（Case A 真实数据下的实际状态）
- **画面内容**：显示「目前没有需要你处理的事项：本学期方案里没有等待你确认的调整。」
- **⚠️ 必须如实说明**：Case A 的 23 项评估里 **0 项是"已确认需补修"**（12 项已满足 + 11 项待人工确认），
  因此本次真实数据下**没有**可提出的换班候选。这张图证明的是**系统不会硬凑建议**，而不是换班能力不存在。
- **⛔ 不得**用这张图证明"系统会推荐换班"，也⛔ 不得用旧版替换型样例冒充本次结果

### 09_需要你处理待确认中心.png
- **取景**：页面唯一的待确认中心，包含「需要进一步确认」分组
- **用途**：证明待确认事项统一归口、去重、翻译成中文，原始代码收在「查看技术详情」
- **可见文字**：分组标题与条数、「查看其余 N 项」折叠、「系统不会替你下结论，需要人工确认」
- **不能证明**：不证明所有冲突都已发现

### 10_未来学期路径.png
- **取景**：未来学期修读路径（多个学期）
- **用途**：证明跨学期闭环，且未来学期只有课程级信息
- **可见文字**：真实学期标签 + 培养方案第 N 学期 + 课程名 / 课程号 / 学分 / 必修或选修 + 建议学分 + 负荷标签
- **⛔ 关键**：画面中**没有**教学班号、教师、星期、节次、教室、校区、容量
- **不能证明**：不证明未来学期真的会开这些课

### 11_选修学分进度.png
- **取景**：选修学分进度区块
- **用途**：证明学分账目算清楚，且证据不足时不编数字
- **可见文字**：最低学分要求 / 已确认完成 / 本学期已选 / 规划前缺口 / 本次规划 / 规划后仍缺
- **核对等式**：最低要求 − 已确认完成 − 本学期已选 = 本次规划 + 规划后仍缺

### 12_数据范围声明.png
- **取景**：「本次规划数据」范围区块
- **用途**：用于回应评委关于数据范围的追问
- **可见文字**：南校园 + 深圳校区、4069 条、全校完整学期数据为否
