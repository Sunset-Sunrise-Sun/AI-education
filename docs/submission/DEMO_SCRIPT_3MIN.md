# 学航·转衔 · 3 分钟评委演示脚本

> 用途：评委现场演示的逐句脚本与操作说明。
> 总时长 3 分钟（180 秒）。时间分配见文末。
> 演示**不从技术开始**，从学生的真实处境开始。
> 事实基线：最终产品 HEAD = 最终 RC HEAD = `695834a45905166321422eeeef0d8f46c83add0d`（2026-10-07）。
> 按钮名与区块名**逐字取自最终界面**，见文末《按钮名对照表》。
> 现场截图见 `docs/submission/screenshots/`。

## 演示前 30 秒的准备（不进计时）

- 后端与前端已按运行手册启动；
- 成绩单 PDF 已放在桌面，文件名不含姓名学号；
- 浏览器窗口干净：**关闭无关标签、关闭开发者工具**；
- 页面已滚动到最顶部，停在"第一步：上传成绩单"；
- 先空跑一遍，确认第 5 步「加入本学期方案」有可选候选（本次真实数据下应有 3 门）；
- 如果后台数据没准备好，按最后一节《应急方案》处理。

| 讲什么话 | 「先不讲技术。我想请大家想一个具体的人：一个大二学生，刚转完专业。他手上有三样东西：一份成绩单、一份新专业的培养方案、一个还没排完的课表。<br><br>他真正要回答的不是'选哪门课'。他要回答七个问题：我已经修过什么、目标专业还缺什么、哪些必须补、本学期真实有哪些班能上、课表冲不冲突、哪些必须问老师、后面几个学期怎么接。<br><br>这七件事现在散在四个地方。他只能靠截图和记忆拼。这就是我们要解决的问题。」 |
| ⛔ 不要讲 | 「我们的技术架构是……」 「我们用了 Agent 编排……」 |

## 第 4 步 · 规划层确认与撤销（1:10 – 1:40）

| 项 | 内容 |
|---|---|
| 点哪里 | 在「补修缺口分析」里，**逐条**点某一行的「确认可转换」；**先念披露句，再点**；等结果回来后指着该行的「撤销确认」 |
| 屏幕展示 | 确认面板首句：「下表「待人工确认」项可逐条选择**确认可转换**（基于你的确认、仅用于本次规划；不是学校官方认定结果，也不会修改学校教务系统记录）。」；确认后出现「已按你的确认移入「已满足」（N 项）—— 基于你的确认、仅用于本次规划；不是学校官方认定结果」，被确认的条目带「基于你的确认」标记与「撤销确认」 |
| 讲什么话 | 「这里是最能体现我们设计取向的一步。这 11 项需要人工确认，但学生不能干等着。所以他可以逐条点'确认可转换'。<br><br>请注意这行字，我们写在操作上面：**基于你的确认、仅用于本次规划、不是学校官方认定结果，也不会修改学校教务系统记录**。<br><br>也就是说，我们允许学生带着假设往前走，但**不允许把假设说成结论**。确认之后，系统按'本次规划已满足'重新算了一遍方案，而且每一条都能**撤销确认**。<br><br>那 23 项 / 12 项 / 11 项的事实口径没有变——用户的确认是**规划假设**，不是把学校的认定搬过来了。」<br><br>（如果评委问"这和学校认定有什么区别"）「区别在责任主体。课程等不等价是学校说的，我们只让学生的规划假设显式化、可追溯、可撤销。页面上的标记写的是'基于你的确认'，不是'学校已认定'。」 |
| ⛔ 不要讲 | 「用户确认后学校就认定这门课等价了」 「AI 自动认定课程等价」 「系统自动批准补修认定」 「学校已经确认」 |

| 讲什么话 | 「第四步，本学期专业选修。系统先从当前学期**真实教学班**里筛出可行候选，注意它只标出**已确认不冲突**的那些。<br><br>规则很明确：只有一个无冲突教学班时，可以直接加入；如果有多个无冲突教学班，系统**不会替你挑一个**，必须你自己选；如果只有未知或已冲突的班，它不会给你加入按钮，只会说明原因。<br><br>加入之后显示'已加入本学期方案'，并且标明这是**规划草稿**，不代表已经完成教务选课；随时可以撤销。<br><br>（如果评委追问候选是否完整）「本次真实数据一共 10 门候选，默认显示前 6 门、其余可展开，也可以直接按课程名或课程号筛选。之前有一版界面对候选设了显示上限，把这个专业选修池里几门重要的课藏在了视野之外——现在候选不再被截断，比如数据库系统原理和数据库系统实验都可以直接筛出来加入。」 |
| ⛔ 不要讲 | 「系统自动替学生选课」 「自动教务选课」 「自动决定教学班」 「系统识别到学生这学期选了数据库课」 |

|---|---|
| 点哪里 | 滚到「未来学期修读路径」区块 |

## 演示时不能讲的词（贴在显示器边上）

### 一、能力不实类

| ⛔ 不要讲 | ✅ 改成 |
|---|---|
| AI 已经自动推理并规划 | 固定工具编排，AI 增强待接入 |
| 用大模型理解了这份培养方案 | 规则和结构化数据在做判定 |
| 用了 GraphRAG / 知识图谱推理 | 当前没有接入 |
| 用 CP-SAT / ILP 求出了全局最优 | 受限的确定性检查与候选评估 |
| 这是最优方案 | 这是建议方案，不是最优解 |
| 系统自动帮你换班 / 自动选课 / 自动注册 | 必须学生本人确认后才应用 |
| 系统自动认定课程等价 | 一律待人工确认；用户可以确认，但那是规划假设 |
| 用户确认后学校就认定了 | 界面写的是"基于你的确认、不是学校官方认定结果" |
| 系统自动帮学生加了选修 | 学生自己点「加入本学期方案」；多候选还要自己选教学班 |
| 系统预测了未来学期的课表 / 教师 / 教室 | 未来学期只有课程级，不预测 |

### 二、数据范围类

| ⛔ 不要讲 | ✅ 改成 |
|---|---|
| 全校完整课程数据 | 南校园 + 深圳校区的真实教学班数据，共 4069 条 |
| 完整学期数据 | 两个校区的 scoped 数据（页面标注"全校完整学期数据：否"） |
| 数据都是真的 | 教学班是真实 scoped 数据；上传的成绩单不参与已满足判定，须分别表述 |
| 教师数据已经完整覆盖 | 当前快照未保留教师字段，教师信息暂未同步，系统不编造 |
| **原始教务接口没有教师信息** | **当前 accepted 快照未保留教师字段，因此教师信息暂未同步**（原始接口有该字段） |
| 已经连上学校教务系统 | 当前不联网抓取，使用本地已验收数据 |
| **系统识别到学生这学期选了数据库课** | 数据库课是**可查询的选修候选**；本次当前课表输入为空，只有用户明确加入才计入负荷 |

### 三、结论强度类

| ⛔ 不要讲 | ✅ 改成 |
|---|---|
| 需要补修 23 门课 | 23 项历史培养要求评估，12 项已确认满足，11 项待人工确认 |
| 这 11 项就是你要补的课 | 这 11 项还需要人工确认 |
| 专业选修要修 23 门课 | 专业选修最低要求是 23 学分 |
| 这个班没有冲突 | 在已知信息范围内未发现冲突（信息未知时仍然只能说未发现） |
| 这门课没有排课信息，所以不用上 | 排课信息待核验，属于未知，不等于没有课 |
| 所有偏好都已经满足 | 未被执行的部分如实列在待确认事项里 |
| 未来学期学分上限是 30 | 当前学期上限是 30，**未来学期硬上限是 35**，两者不同 |
| 界面按必修 / 专选 / 公选给课程分类 | 本轮界面是课表**来源图例**，不是课程属性标签 |

## 如果出现 UNKNOWN / 待确认，怎么解释

现场一定会出现"待核验""待人工确认"这类字眼。**不要躲，主动讲，这是加分点。**

### 统一话术（三段式）

> 「这一条显示的是**待核验**。它的意思是：**当前数据里没有足够信息下结论**。
> 我们不猜。宁可告诉学生'这里还不知道'，也不给他一个看起来完整、实际错误的答案。
> 这一条会进入待人工确认清单，由他本人或者老师去确认。」

### 分类型速查

| 页面上出现 | 它的准确含义 | 现场怎么说 |
|---|---|---|
| 排课信息待核验 | 这个教学班在数据里没有可用排课信息，属于未知 | 「数据里没有这个班的排课信息。**这不等于没有课，也不等于不冲突**，是还不知道。」 |
| 教师信息暂未同步 | 当前 accepted 数据快照未保留教师字段 | 「教师这一列在当前数据快照里没有保留，所以写'暂未同步'。**系统不编造教师姓名**。原始接口是有教师字段的，是这次保存的白名单没有留下它。」 |
| 待人工确认 | 涉及课程等价、学分差额、学院政策、条款歧义 | 「这类结论属于学校的正式规则，**系统不下结论**，只把依据列出来交给人。学生可以带着规划假设往前走，但页面会写明那不是官方认定。」 |
| 需要明确选择 | 输入下没有确定不冲突的候选 | 「系统没有找到确定不冲突的替代教学班，所以**不硬凑**，把选择交回给学生。」 |
| 缺少数据 | 某个字段或某项依据缺失 | 「这里是数据缺失，我们如实标出来，不补一个默认值。」 |
| 选修学分进度显示"—" | 证据不足，无法确认归属 | 「这一项证据不足，我们就显示一横线，**不编一个数字**填进去。」 |
| 未来学期某段写"暂不需要额外安排课程" | 该学期确实不需要安排课程 | 「这是系统如实说明，不是漏排。它不会为了填满学期而编课。」 |
| 未来学期没有教师和时间 | 结构上就不允许出现 | 「未来学期**只做课程级规划**，这些字段在结构上就不会产生。」 |

### 一句话兜底

> 「凡是系统不能确定的，它都会说是**待确认**，而不是给一个答案。这是我们有意做的设计。」

## 应急方案

| 现场情况 | 怎么处理 |
|---|---|
| 后端没起来 / 页面报错 | 直接用 `docs/submission/screenshots/` 里的截图讲同样的脚本（`SCREENSHOT_INDEX.md` 有逐张配文），**明确说这是截图**，⛔ 不要假装是实时系统 |
| 生成方案很慢 | 一边等一边讲第 4 步的确认机制，讲完再刷新 |
| 某个数字和排练时不一样 | **以现场页面为准**，⛔ 不要念排练时记下的旧数字 |
| 教师列整片都是"暂未同步" | 主动说明：「当前数据快照没有保留教师字段，所以教师信息暂未同步，这是我们已经确认过的限制；系统选择如实说明而不是编名字。」 |
| 选修建议里没有想讲的课 | 用课程搜索框按课程号直接查（例如 `CSE335`），说明候选可以从真实教学班数据里查到 |
| 评委追问"AI 在哪里" | 「产品方向上有 AI 的位置：未来由模型辅助理解输入、检索证据、生成解释。当前版本执行的是规则、结构化数据和固定编排。」 |
| 评委追问"是不是自动选课" | 「不是。选修必须学生自己点'加入本学期方案'，加入的也只是规划草稿；选课和注册仍然由学生和学校完成。」 |
| 评委追问"用户确认算不算认定" | 「不算。页面上写的是'基于你的确认、仅用于本次规划、不是学校官方认定结果'，而且可以撤销。」 |
