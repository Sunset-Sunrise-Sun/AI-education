## 如果出现 UNKNOWN / 待确认，怎么解释

现场一定会出现"待核验""待人工确认"这类字眼。**不要躲，主动讲，这是加分点。**

### 统一话术（三段式）

> 「这一条显示的是**待核验**。它的意思是：**当前数据里没有足够信息下结论**。
> 我们不猜。宁可告诉学生'这里还不知道'，也不给他一个看起来完整、实际错误的答案。
> 这一条会进入待人工确认清单，由他本人或者老师去确认。」

### 分类型速查

| 页面上出现 | 它的准确含义 | 现场怎么说 |
|---|---|---|
| 排课信息待核验 | 这个教学班在数据里没有可用排课信息，属于未知 | 「意思是数据里没有这个班的排课信息。**这不等于没有课，也不等于不冲突**，是还不知道，所以我们按未知处理。」 |
| 教师信息暂未同步 | 当前 accepted 数据快照未保留教师字段 | 「教师这一列在当前数据快照里没有保留，所以写'暂未同步'。**系统不编造教师姓名**。要说清的是：原始接口是有教师字段的，是我们这次保存的字段白名单没有留下它。」 |
| 待人工确认 | 涉及课程等价、学分差额、学院政策、条款歧义 | 「这类结论属于学校的正式规则，**系统不下结论**，只把依据列出来交给人。」 |
| 需要明确选择 | 输入下没有确定不冲突的候选 | 「系统没有找到确定不冲突的替代教学班，所以**不硬凑**，把选择交回给学生。」 |
| 缺少数据 | 某个字段或某项依据缺失 | 「这里是数据缺失，我们如实标出来，不补一个默认值。」 |
| 选修学分进度显示"—" | 证据不足，无法确认归属 | 「这一项证据不足，我们就显示一横线，**不编一个数字**填进去。」 |
| 未来学期没有教师和时间 | 结构上就不允许出现 | 「未来学期我们**只做课程级规划**，这些字段在结构上就不会产生，不是没显示出来。」 |

### 一句话兜底

> 「凡是系统不能确定的，它都会说是**待确认**，而不是给一个答案。这是我们有意做的设计。」

---

## 应急方案

| 现场情况 | 怎么处理 |
|---|---|
| 后端没起来 / 页面报错 | 直接用 `[待最终截图]` 的截图讲同样的脚本，**明确说这是录像/截图**，⛔ 不要假装是实时系统 |
| 生成方案很慢 | 一边等一边讲第 4 步的确认机制，讲完再刷新 |
| 某个数字和排练时不一样 | **以现场页面为准**，⛔ 不要念排练时记下的旧数字 |
| 教师列整片都是"暂未同步" | 主动说明：「当前数据快照没有保留教师字段，所以教师信息暂未同步，这是我们已经确认过的限制；系统选择如实说明而不是编名字。」 |
| 评委追问"AI 在哪里" | 「产品方向上有 AI 的位置：未来由模型辅助理解输入、检索证据、生成解释。当前版本执行的是规则、结构化数据和固定编排。」 |
| 评委追问"是不是自动选课" | 「不是。我们输出的是建议方案和待确认事项清单，选课和注册仍然由学生和学校完成。」 |
| 评委追问"为什么一门课有这么多候选" | 「真实数据里一门课可能有几十个教学班，所以我们按课程分组、默认只显示 3 个候选，其余折叠。这是一个我们专门改过的可用性问题。」 |

## 演示红线（讲错一次就会失分）

1. ⛔ 不说"要补 23 门课"；
2. ⛔ 不说"专业选修要修 23 门课"（那是 23 学分）；
3. ⛔ 不说"AI 已经自动推理"；
4. ⛔ 不说"全校完整数据"；
5. ⛔ 不说"自动换班 / 自动选课"；
6. ⛔ 不说"未来学期有课表 / 教师 / 教室"；
7. ⛔ 不说"教师数据已完整覆盖"，也不说"原始教务接口没有教师信息"；
8. ⛔ 不说"未来学期每学期 35 学分"（当前硬上限是 30）；
9. ⛔ 不说任何未经验证的数字（准确率、成功率、用户量）。
