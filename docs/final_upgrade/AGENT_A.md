## 目标
保留旧 Case A，新增**仅在现有已验证版本和规则范围内**的个人规划入口：选择源/目标培养方案版本、上传/提供本人已修记录、独立核对与计算，结果不复用其他学生的已修事实或个案认定。先做后端可信能力，不为追求展示面扩大支持范围。

## 工作顺序及任务
1. **盘点与基线：** 查找真实 Case A 输入组装、CurriculumVersion、课程识别/成绩上传路径、PlanResult、Planner、选修新增/调整路径；运行可行基线测试，记录已知失败。不得假设路径一定是旧对话所述名称。
2. **培养方案目录：** 优先复用已有真实版本及读取器，提供可查询的适用版本元信息（年级/校区/方向/来源/核验状态）。如现有通用 JSON 无法表达某种规则，不允许自创并冒充已支持；Mock 一律显式 Mock，未知方案不开放选择。首期不新增数据库。
3. **独立学生输入：** 在非公共契约范围新增请求/组装能力，接受所选版本 ID、学生本次成绩/已修事实、课程身份核对、已有正式认定凭据或明确标注的规划假设、可用偏好与现有课表；服务端校验版本兼容/输入完整性/来源。成绩单上传若仅产出草稿，则必须经独立流程确认并进入缺口计算，不能凭文件名更新宣称成功。
4. **严格语义：** 目标培养要求对本人已修及有效认定进行核对；未找到记录不必然是确证缺口；课程身份确认不等同学校转换审批；不允许从 Case A 继承 satisfied 状态或授信结论。保留 `required / possibly_equivalent / manual_confirmation / satisfied` 等已定义的状态含义。
5. **规划接入：** 复用原 Curriculum→MakeupTask[]→Planner 路线，不在 Planner 内另写认定。若某现有接口不能支持新流程，不动 /schemas 或 /docs/interfaces，能做的先实现，受阻项记录 BLOCKED。旧 Case A API 不回归。
6. **确定性修复：** 定位选修新增通道，防止多门新增相互时间/周次冲突、已选与新增冲突及总学分上限越界被错误接纳；需要检验原课表+累计新增集合；已存在的超限课表仅提示而不篡改。确认真正生效的偏好，未生效的不得声称已执行。只修改自己职责中的校验逻辑，不更改公共优化目标。
7. **可选极简前端：** 若能在不与 B 冲突、不更改共用入口的情况下显示版本/成绩预览与当前结果状态，可单独封装；否则留下联调说明，不扩张范围。

## 验收用例
- 同一已支持目标方案 + 两份独立脱敏/Mock 成绩输入分别计算，产生**基于真实输入差异的可解释不同状态**；测试断言具体原因，不以简单不等号代替。
- 切换培养方案或成绩后旧结果/学生确认不可错用。
- 不支持版本、未核验规则、空/错误输入、模糊成绩、未知等价一律明确拒绝或留待核验，不能回退固定 Case A。
- 两门新增彼此冲突、周次不重叠、超学分上限、原课表已超限、重复添加等边界测试。
- 原 Case A 正常；已有测试尽可能全回归。记录实际命令和成功/失败数量。
