# 学航·转衔｜比赛演示脚本（3–5 分钟）

> 适用分支：`feature/final-upgrade-ux-polish`（基于 `feature/final-upgrade`）。
> 配套文档：`docs/final_upgrade/DEMO_ACCEPTANCE_RUNBOOK.md`（档位与验收边界）、
> `docs/final_upgrade/reports/UX_POLISH_REPORT.md`（本轮改动）。
>
> **本脚本只演示已实现的能力。** 三类内容必须当场说清：
> ① Mock 演示数据；② 前端预览（fixture）；③ 规则解释（非 AI）。

## 0. 开演前 5 分钟检查（不占演示时间）

```powershell

cd backend
python -m uvicorn app.main:app --reload          # 确认 http://127.0.0.1:8000/health 可访问
```



开演前确认三件事：

1. 顶部三个入口都能点：**转专业分析 / 补修路径 / AI 调整**；
2. 页面上凡是预览数据处都有 **「仅前端预览」** 标注；
3. 解释面板显示 **「规则模板（非 AI）」**。

> ⚠️ 若使用档位 B（真实后端），`/api/v1/ai-planning/status` 默认 `enabled=false`，
> AI 调整会如实显示"未启用"——**这是正确状态**，不要当成故障，也不要硬演成成功。

## 2. 分步脚本（逐步操作 + 建议讲解）

### 0:00–0:30　背景与定位

**操作**：停留在默认页（**补修路径**），先不点击。

**建议讲解**：

> "我们的用户是**已经转完专业**的学生。他的问题是：新专业的培养方案我缺哪些课、
> 为什么缺、这学期和后面几学期怎么补、能不能直接说出需求让系统帮我调。
> 这个页面就是回答这五个问题的。"

**注意**：不要描述成"智能选课推荐"或"聊天机器人"。

---

### 0:30–1:10　① 转专业分析：到底缺什么

**操作**：

1. 点顶部 **「转专业分析」**；
2. 页面顶部会出现醒目的**缺口摘要**（大数字 + 三个分项）；
3. 指出提示行里"可能等价 / 待人工确认**不是**已认定通过"。

**建议讲解**：

> "第一眼看到的就是结论：**还需要补修 2 门**。
> 旁边三项分别是已满足、可能等价、待人工确认。
> 注意这里的措辞——可能等价和待人工确认**不算通过**，必须人工确认后才会改结论。"

**⚠️ 声明（必须说）**：本档位下版本目录来自**前端预览**，页面已标注「仅前端预览」。
真实环境需要负责人提供**已核验**的培养方案目录；目录缺失时页面会明确显示"没有已核验版本目录"。

---

### 1:10–1:50　② 补修路径：当前学期 + 后续学期

**操作**：

1. 点 **「补修路径」**；
2. 先把顶部**阅读顺序条**（① 当前学期课表 → ② 后续学期路径 → ③ 优先级/风险/待确认 →
   ④ 规划结果明细 → ⑤ 解释与依据）念一遍；
3. 依次下滚：当前学期课表 → 后续学期路径 → 风险与待确认 → 规划结果明细；
4. 最后指出"支撑数据与后端明细"分区，说明它只是原始依据。

**建议讲解**：

> "这页我按**阅读顺序**排好了：先看这学期实际排了哪些班，
> 再看后面几学期要补什么，然后看哪里可能出问题，最后才是完整的方案明细。
> 最下面是原始数据（缺口逐条判定、教学班供给、偏好），它本身不产生新结论。"

**⚠️ 声明**：当前展示的是 **Mock 演示数据**（页面每块都有 Mock 标记）。

---

### 1:50–2:20　③ 查看依据：为什么这样判定

**操作**：

1. 在"历史培养要求评估"或"规划结果"区点 **「🔍 查看依据 / 为什么这样安排」**；
2. 展开后指出：**生成方式** 标签、**直接依据（强证据）** 的来源字段与原始取值、
   以及**仍需人工确认**的事项。

**建议讲解**：

> "每一条结论都能追到来源：哪个对象的哪个字段、原文是什么。
> 请注意右上角这个标签——**规则模板（非 AI）**：这是按规则拼出来的解释，
> 没有调用任何大模型。系统不会替学校下结论，需要人工确认的会单独列出来。"

---

### 2:20–4:20　④ AI 调整：两次确认（本轮重点）

#### 2:20–2:45　说出需求

**操作**：

1. 点顶部 **「AI 调整」**；
2. 停一秒让观众看到：醒目的**一句话入口**、**示例语句**、
   以及常驻的 **「当前调整对象」** 卡片；
3. 点示例 **「这学期太累，尽量别在周五上课」** → 右侧抽屉打开并**预填**这句话。

**建议讲解**：

> "用户不需要懂术语，说人话就行——比如'太累''尽量别在周五'。
> 注意面板上方一直写着**当前调整的是哪一份方案**，AI 不会改到别的方案上。"

#### 2:45–3:20　第一次确认：意图

**操作**：

1. 点 **「🧠 让 AI 解析这句话」**；
2. 指向抽屉顶部的**阶段指示**（说出需求 → 确认意图 → 查看候选 → 确认采用）；
3. 在草稿里指出三块：**硬约束 · 不可协商**、**软偏好 · 可协商**、
   **本学期学分上限**（显示"未指定"）；
4. 读一遍那句提示："**页面不会替你猜一个默认值**"；
5. （可选）在学分上限里填 `22`，展示它会带上"依据：用户在确认面板填写"。

**建议讲解**：

> "第一步不是直接改方案，而是先确认'AI 理解得对不对'。
> 我们把**不可协商**和**可以商量**分成两块——硬约束违反会被后端直接拒绝。
> 学分上限它没说就是'未指定'，**系统不会替你猜**；要加就自己填。"

#### 3:20–3:50　求解 → 候选对比

**操作**：

1. 点 **「✅ 确认意图并生成候选方案」**；
2. 求解过程中指出提示："**没有进度百分比**，完成前不会显示任何课程"；
3. 候选出现后，先读 **变化摘要**（新增 / 移除 / 换班 / 保持 / 学分），
   再往下看 **换班的旧班 → 新班**、风险、未决事项。

**建议讲解**：

> "确认之后后端才去求解。求解期间我们**不显示假进度、也不先塞一个占位方案**。
> 出来后第一眼是变化摘要：新增几门、移除几门、换了几次班、学分变化多少。
> 这些都是**后端确定性算出来的差异**，不是模型编的。"

#### 3:50–4:20　第二次确认：采用或保留

**操作**：

1. 指向按钮上方的**采用说明**（"本次运行期间""不会保存""不代表教务系统已完成选课"）；
2. 点 **「✅ 采用候选方案（临时）」**；
3. 展示结果：**进程内会话版本 N**，以及"未持久化、重启失效"的提示；
4. 关闭抽屉 → 方案区已刷新；再打开解释入口，说明解释会基于**刷新后的方案**。

**建议讲解**：

> "第二次确认才决定用不用。**只有后端确认采用成功，页面才会换方案**；
> 拒绝、过期、失败时原方案一个字都不改。
> 而且这里必须说清楚：这只是**本次运行期间**的临时状态，没有存到账号，也不是学校选课成功。"

---

### 4:20–5:00　⑤ 风险与边界（诚实收尾）

**操作**：

1. 停在方案风险 / 未决事项；
2. 展开页面底部**数据声明**。

**建议讲解（照实说，不要拔高）**：

> "最后是边界。三条我们绝不模糊：
> **一，** 现在演示用的是 Mock 演示数据和前端预览，页面都标了；
> **二，** 规则解释是**模板**，不是大模型；
> **三，** 真实的 DeepSeek 在线调用、真实培养方案目录、真实教学班快照**还没有完成验证**——
> 后端没配置时页面会明确说'不可用'，不会拿假结果补上。"

## 4. 常见提问与回答口径

| 提问 | 回答 |
| --- | --- |
| 这是大模型自己排的课吗？ | 不是。排课来自后端**冻结的确定性 Planner**；模型只负责把你的话解析成约束，而且输出要过校验。 |
| 解释是 AI 写的吗？ | 不是。解释是按字段拼出来的**规则模板**，界面标了"非 AI"。 |
| 为什么会显示"未启用 / 不可用"？ | 服务端没开 `AI_PLANNING_ENABLED` 或没注入密钥。这是**如实状态**，我们不会拿 Mock 顶上。 |
| 采用了就等于选上课了吗？ | 不是。只是本次运行期间页面方案临时变了，未持久化，也不代表教务系统选课成功。 |
| 能不能自动跨学期重排？ | 当前**不支持**，后端会返回 `blocked`；我们不会假装能做。 |

## 5. 演示禁忌（本轮明确定下的红线）

- ⛔ 不要把 Mock / 预览数据说成真实教务数据；
- ⛔ 不要把规则模板解释说成 AI 生成；
- ⛔ 不要在 `/status` 显示不可用时，用别的数据演成"AI 已调整成功"；
- ⛔ 不要声称已接入真实 DeepSeek 在线模型（除非当场一次受控 `POST /interpret`
  返回 `generator_kind=deepseek_live`）；
- ⛔ 不要演示 `exclude_course`、跨学期自动重排等**尚未支持**的能力。

---

## 6. 演示后如需重置

1. 刷新页面即可回到初始状态（进程内会话不会持久化）；
2. 若要换档位，修改 `frontend/.env.local` 后**重启** `npm run dev`；
3. 不要在前端或 Git 中写入任何密钥；密钥只放在服务器进程环境里。
