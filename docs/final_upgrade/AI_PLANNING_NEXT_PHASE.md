# 学航·转衔｜下一阶段 AI 交互式补修规划开发纲要

状态：**方案冻结草案；尚未授权修改公共契约；不得据此跳过现有两个 Builder 的 Architecture Review**。

## 0. 产品边界
用户是**已转专业的学生**，核心问题是新旧培养方案衔接、补修缺口、正常课程与补修课协调、当前及后续学期规划。不是一般推荐选修课的通用选课助手。现实中的课程认定、毕业要求仍以学校为准。
当前学期按真实教学班做节次/周次/校区校验；未来学期没有确认的教学班时只做课程级条件规划，缺乏证据不得声称未来必定开课。

## 1. 交互五步
1. 学生自然语言提出补修目标（如“尽量大三前补完，当前学期不要超 25 学分，优先保留专业核心课”）。
2. **AI 只生成结构化意图草稿并分析当前计划**：列出明确条件、待消歧意图、来源与可执行工具能力；不猜默认值、不开启修改。
3. **用户确认即将执行的调整**：明确哪些是硬约束、哪些是软偏好；哪些课程禁止移除；修改范围仅本学期还是包括未来学期。确认前不得执行任何会更新方案状态的动作。
4. AI 规划控制器以受限工具集请求现有 Curriculum/Planner（只允许合法参数）：候选方案生成、教学班搜索/换班、负荷评估、课程级路径重排；后端校验学分、时间、周次、先修、认定证据与数据覆盖情况。未知原因必须暴露，不允许 LLM 自行计算合法性。
5. 展示 **原方案/候选方案差异、代价、风险与未解决项**，由学生第二次确认是否采用。拒绝则原方案完全不变，允许撤销。

## 2. 规划质量目标（必须渐进实现）
- 最基本保证：正式规则、有效先修、课表时间冲突、已声明学分上限、学生显式锁定课程不被破坏。
- 可以优化：紧急补修优先、学期负荷平衡、跨校区、空档、连堂、尽量在用户设定日期完成。
- 不允许对“少上点课”“更轻松”直接凭空推导学分数或视作强制规则；先让用户选择建议范围。
- 优化权重由学生确认的偏好决定；AI 不得为了求出方案自动放宽硬约束。
- 无解必须给出证据支撑的不可满足原因及可供用户选择的调整方向（不能假造课程）。
- 多候选必须由实际 Planner 求解或检验产生，并标记每项指标的计算来源。

## 3. 工具与数据契约设计原则
第一阶段先写 `docs/final_upgrade/PLANNING_AGENT_INTERFACES_PROPOSAL.md` 进行 Review，**不要直接修改** /schemas/ 或 /docs/interfaces/。提议最小化以下边界，具体字段以现有契约为准：
- inspect_current_plan：查询只读学生计划/课程事实及数据来源；
- parse_adjustment_intent：LLM 输出严格 JSON（硬约束、软目标、锁定课程、范围、歧义），本地校验；
- preview_adjustment：返回可人工核对的拟执行变更，不修改当前计划；
- solve_candidate：通过已有 Planner/课程级路径工具求解并验证；
- compare_plans：比较学分、补修完成节点、课程/班次差异、风险/未知；
- adopt_candidate：必须凭绑定了输入摘要的用户确认令牌执行，禁止隐式采用；
- revoke_candidate/adoption：支持撤销或返回先前已确认版本。
只有在已有实现支持时才开放相应工具，不可用工具返回明确不支持。

## 4. 前端产品
三个主区块/页面：
- **转专业分析**：源与目标专业、入学年级和适用培养版本、成绩核对、认定待办、缺口状态；
- **补修路径**：当前学期教学班安排、未来课程级路径、风险与学分负荷；
- **AI 调整**：右侧会话抽屉（手机全屏），意图确认表单、生成中、候选与原案差异、采用/拒绝/撤销。
不得把 AI 面板做成脱离当前方案状态的泛用聊天框。缺数据或没有接入真实 LLM 时必须诚实说明，不用伪造 AI 回复。

## 5. 并行开发隔离
下一轮必须从**通过合并与回归的** feature/final-upgrade 派生，不能从未验收的 A/B 分支直接开始。
- 新 Agent A：Planning Controller + Planner 能力盘点与小范围优化；不改前端，不动公共契约直到负责人签批。
- 新 Agent B：三页面信息架构 + 确认/对比/撤销 UI；先使用显式 Mock 合约/适配层，不猜 A 私有字段，不改 Planner。
- 保留 main 不动，单独 draft PR 对 feature/final-upgrade；验收后才能合并。
- 第一版优先只实现**当前学期教学班更换和已支持的负荷调整**；跨学期自然语言调整必须等课程级重规划真实能力验收后开启，不以静态语言生成代替规划。

## 6. 必要材料/上线门槛
- 至少一套有出处且已核验的源和目标培养方案版本，正式认定/课程等价与学生假设严格区分；
- 至少两份经授权、脱敏且彼此独立的学生成绩，覆盖个人计算；
- 至少一个可核验的真实教学班快照（未覆盖校区/学期清楚标注）；
- 经负责人批准的模型提供方、发送数据字段白名单、API key 注入方式、成本上限；不提交任何密钥；
- 回归现有 Case A；新 Planner 行为、候选校验、前端状态和 Mock/Real 标签全部通过测试。

## 7. 当前已知风险
Agent A 目前的两人输入演示是 Mock，未装配真实已核验目录或实际教务供给；Agent B 目前解释是规则模板（有模型适配接口，但未真正接入外部 LLM）。这两项不可写成“已实现真实个性化 AI 规划”。
