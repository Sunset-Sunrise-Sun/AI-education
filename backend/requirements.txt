# python-docx **只是测试依赖**，⛔ 不是运行期依赖。
#
# 判定依据（已逐处核对）：
# - `app/curriculum/docx_reader.py` **不 import docx**：它把 .docx 当作 OOXML 包，
#   用标准库 `zipfile` + `xml.etree.ElementTree` 直接读 `word/document.xml` 等部件
#   （这也是它能做「有界读取 / 拒绝重复成员 / 拒绝路径穿越」的原因）。
#   生产代码里对 `docx` 的其它出现都只是**变量名/字段名**（如 `record["docx"]`），不是模块导入。
# - 只有两个测试文件 `from docx import Document`，用途是**构造**测试用的 .docx：
#   `tests/test_curriculum_elective_group.py`、`tests/test_curriculum_positional_docx.py`。
#
# 为什么仍然写进这个文件：README 与本文件顶部约定的安装命令只有
# `python -m pip install -r requirements.txt` 一条（CI 也用同一条）；
# 为了不让"运行一条命令就能跑测试"的承诺失效，测试依赖与运行期依赖暂时共处一文件。
#
# ⚠️ 这条依赖曾经缺失（只在开发机上有、未声明），导致 CI 首次运行在
# Linux + Python 3.12 上收集阶段 `ModuleNotFoundError: No module named 'docx'` 而失败。
